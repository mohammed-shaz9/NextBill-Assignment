01Problem & approach

Classify free-text invoice lines into an expense category so bookkeeping can be automated.

Input{"text": "Blue Dart courier charges for warehouse delivery"}
Output{"category": "Logistics", "confidence": 0.93, "alternatives": [...]}
ClassesLogistics · Office Supplies · Cloud/Software · Utilities · Travel · Inventory · Unknown (low confidence → human review)
ModelFully learned. TF-IDF word + character n-grams → best of 3 linear classifiers chosen by cross-validation. No keyword rules.
WhyShort, brand-heavy text (BESCOM, Zoho, Delhivery). Sparse linear models: ~1 ms inference, ~1 MB artifact, explainable, retrain in seconds. A transformer adds hundreds of MB for little gain on 6 classes.

05ML pipeline

  1. Load training data + any human feedback; drop unknown labels.
  2. Deduplicate: the generator emits ~30% duplicates that would leak across the split.
  3. Stratified 80/20 split (seed 42).
  4. Select model with 5-fold stratified CV on macro-F1:
    CandidateClassifier
    logregLogisticRegression, C=10, class_weight=balanced
    linear_svc_calibratedLinearSVC wrapped in CalibratedClassifierCV (true probabilities)
    complement_nbComplementNB, alpha=0.3
    All share features: word (1–2)-gram + char_wb (2–5)-gram TF-IDF, sublinear tf.
  5. Report classification report + confusion matrix on the 20%.
  6. Realistic eval on hand-written set.
  7. Refit winner on all unique data → trained_model.pkl; scores → metrics.json.

07Evaluation

Synthetic data is template-based, so 1.00 only proves the plumbing. Trust the realistic number. Current misses: "Jio postpaid mobile bill" → Inventory; "Ball pens notebooks envelopes" → Unknown. The test suite fails if realistic accuracy drops below 75%.
